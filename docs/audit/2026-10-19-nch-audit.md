## What changed after comparing notes
- **GrokBot found what static review couldn't:**
  - the Next.js remote-code-execution advisory, via `pnpm audit`
  - the Moralis 401 storm, from production logs
  - performance numbers, from Lighthouse
  - the AGPL licence issue
  - the `/currencies` "spent" wording
  - the `/burn` buy and payback framing
- **Claude found what GrokBot didn't:**
  - an Ask prompt-injection path that could show a wallet-drainer link
  - the username → wallet lookup (people→wallet rule)
  - "clean ownership" granted when the canvas read failed
  - outages cached as "Token not found"
  - Symphony caching a wrong pinned song for a week
  - the `job_watchdog` grants missing from git (the live database checked out fine)
  - the `my-normies` fan-out
  - unlabelled third-party tools
  - the near-invisible focus ring
- **Upgraded after comparing:** the Next.js advisory goes from GrokBot's "not proven" to **confirmed exploitable condition**. The record-card and Symphony share images put owner-set agent names into `ImageResponse` as text, which is exactly the risky case. An interim mitigation shipped in #128; the upgrade is still required.
- **Where we differ:**
  1. **Pulse usage signal.** #128 counts distinct callers (hashed IP), which stops "8 curls from one script". GrokBot's point stands, though: anyone can rotate IPs, and usage isn't trust. My recommendation (🧭 Ryan) is to take usage out of `pulse_level` and show it as a raw count next to the level. That matches "Pulse = trust, never skill" and "ship raw counts".
  2. **Wallets in `/burn` URLs.** GrokBot rates this Medium; I agree but treat it as a product change, not a bug. `/burn?wallet=` is deliberately shareable. The fix is a fragment (`#wallet=`), so the address never reaches server logs, plus share links without the full wallet (⏳ later; it touches the /burn flow).
