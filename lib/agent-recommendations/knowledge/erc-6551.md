# ERC-6551 (Token Bound Accounts) — Zulo Account Plane

> **Status for Zulo:** optional / **disabled by default** (`ZULO_TBA_PROVIDER_STATUS`)  
> **Identity plane (live):** Normie ERC-721 + ERC-8004 agentId  
> **Account plane (future):** pluggable ERC-6551 provider (Tokenbound V3 defaults)

## What it is

ERC-6551 binds a deterministic smart-contract wallet (token-bound account, TBA) to an NFT. The current NFT holder controls the TBA; the account can hold assets and execute operations. Spec: [EIP-6551](https://eips.ethereum.org/EIPS/eip-6551).

Two pieces:

1. **Singleton registry** at `0x000000006551c19487814612e58FE06813775758` — `account` / `createAccount`
2. **Account implementation** (pluggable) — IERC6551Account (+ optional IERC6551Executable)

Addresses are CREATE2-derived from `(implementation, salt, chainId, tokenContract, tokenId)` and are **receivable before deploy**.

## Zulo mapping (do not conflate)

| Layer | Live today | TBA role |
|-------|------------|----------|
| Normie #7141 | Origin NFT | Binding target for future TBA |
| ERC-8004 agent **32626** | Identity / discovery | Unchanged by TBA |
| Owner / Canvas delegate | Control for CredHub features | Orthogonal; TBA `isValidSigner` is a future control mode |
| Hot wallet | A2A tips narrative | Not a TBA inventory |
| Canvas AP | Per-Normie, non-transferable | Not TBA-held |

**Doctrine:** ERC-6551 is a **swappable account-provider** under `lib/erc6551/`, not a replacement for ERC-8004 or Normie identity.

## Security (encode at product boundary)

- **Ownership cycles:** transferring the bound NFT into its own TBA can lock assets; product blocks depth-1 self-deposit (`assertSafeTbaDeposit`).
- **Sale-time drainage:** out of EIP scope — if TBA inventory is ever marketplace-relevant, bind order validity to account `state`.
- **Never** ask users for seeds; keep fail-closed product language until `live`.

## Related (scope boundary)

- **ERC-7579** — modular smart-account modules; does **not** define NFT→account binding.
- Compose modular execution inside a TBA implementation later; keep address derivation on ERC-6551 registry.
